# 失控寄抽管理系統

**目前最新版：v9.0**

> 版本規則：同一功能群組的小幅調整使用 `v9.1`、`v9.2`；新增下一個完整功能群組才升級為 `v10.0`。歷史細版已重新整併為功能型版本，避免每次小修正都增加主版號。

## v9.0｜營運總覽與實際收款追蹤
### 更新內容
- 整併原 v61～v67 的同類更新，統一為目前正式的營運總覽與實際收款版本。
- 套組管理的「已賺多少」改為顯示進行中套組目前實際收到的款項，不扣套組成本；以實收扣除找零計算，待定、免單結束與折扣全抵不列入。
- 新增銷售的套組搜尋提示同步顯示「已賺多少」，與套組管理採相同計算口徑。
- 營運總覽整理為桌面版 2×2 四格：近三個月成本 vs 銷售額、套組狀態分布、套組成本／銷售額比較、進行中套組「已賺多少」付款方式分區；手機／窄螢幕自動改為單欄。
- 「近三個月成本 vs 銷售額」固定顯示台北時區本月與前兩個日曆月份，避免歷史月份過多造成圖表過寬。
- 進行中套組的已收款會依現金、轉帳、LINEPAY、街口等實際付款方式拆分；多元付款依 `sale_payments` 拆回各付款方式，現金扣除找零。
- 四張總覽圖表的資料元素皆可點擊追查：月份可查看來源套組／交易、狀態可查看對應套組、套組比較可直接開啟明細帳、付款方式可查看每筆收款來源。
- 付款來源明細列出銷售日期、登錄時間、老闆、套組編號、品名、該付款方式實收、整筆銷售額與填表人，並可直接開啟套組明細帳。
- 套組明細帳新增「付款方式收款明細」，顯示該套累積實際已收總額與各付款方式分項金額；每筆交易亦保留付款拆分。
- 營運總覽新增登錄監控資訊：今日已登錄筆數、今日最後登錄時間、資料載入時間與最近一筆登錄時間，用於快速發現現場收款可能漏登。
- 今日登錄判定採 `sales.created_at` 並以 Asia/Taipei 顯示，不受銷售日期補登影響；編輯既有交易不會改寫原始登錄時間。
- 銷售相關的登錄時間統一只顯示 `HH:mm`；銷售日期仍獨立保留，結算等需要辨識日期的歷史時間維持完整日期時間。

## v8.0｜E 店內套與日結制度
### 更新內容
- 整併原 v56～v60 的 E 店內套、套組結算與日結更新。
- E 改為「店內套」模式，不再使用一般寄抽老闆的月結算法；切換至 E 時原「月結報表」改為「套組結算」。
- E 不受寄抽到期日限制，只保留手動啟用／停用；既有到期日清空，資料庫營運判定與前端清單皆同步忽略 E 的到期日。
- 套組結算只處理結束、免單結束、直購、腰斬等已結束套組；進行中套組不列入結算。
- E 改採日結型態：新結束的套組先進入「待結算」，必須按下「結算」後才正式寫入結算時間與結算營收快照。
- 套組結算頁新增「今日應結算」，會自動帶入前日或更早尚未結算的套組並標示「前日未結」，直到實際結算為止。
- 功能上線前已結束的 E 舊套組不回填待結算，全部維持歷史已結算狀態，不影響既有帳務。
- 每個已結束／待結算套組保留「明細帳」，並可查看該套各付款方式累積金額；不再顯示所有套組合併後的付款方式總結算區塊。
- 多元付款會拆回現金、轉帳、LINEPAY、街口等實際支付方式；現金找零會先扣除後再計入淨收款。
- 「全部老闆」的一般月結報表排除 E，避免店內套同時被一般月結與套組日結重複計算。

## v7.0｜老闆狀態、權限與銷售資料安全
### 更新內容
- 整併原 v51～v55 的老闆封存、權限、銷售時間軸、結束標記與套組編號更新。
- 老闆手動停用或寄抽到期後，進行中套組會自動改為腰斬；系統只對「因停用／到期自動腰斬」的套組留下標記，重新啟用後只恢復這些套組，不誤動人工腰斬資料。
- 左側營運對象與新增套組／新增銷售的老闆清單只顯示目前有效的老闆；停用或到期老闆移入封存區，仍可查看歷史資料。
- boss 與 jen 都可新增老闆、修改名稱與英文編碼；停用／啟用仍保留 jen 權限，新增與修改改走安全 RPC，不直接放寬資料表權限。
- 銷售紀錄新增固定時間軸排序鍵，交易建立後順序不因後續編輯而改變；銷售分析與套組明細帳採用相同穩定排序。
- 銷售紀錄新增 `closed_bundle` 永久標記，重新整理後再次編輯仍可知道哪一筆交易曾執行「結束套組」；取消勾選只移除該筆標記，不會自動重新開啟已結束套組。
- 新增套組改由系統依「老闆代碼＋MMDD＋兩位流水號」自動產生，例如 `A092301`；建立當下由 Supabase RPC 再次計算並加鎖，降低多人同時新增撞號風險。
- 保留 `(owner_id, code)` 唯一限制作為最後防線；重複編號錯誤改為中文提示。

## v6.0｜銷售操作、明細帳與月結完善
### 更新內容
- 整併原 v40～v50 的銷售搜尋、套組同步、結束流程、刪除、明細帳與月結整理更新。
- 新增／編輯銷售的套組欄位改為可搜尋下拉選單，可依套組編號、品名、日期即時篩選，並顯示目前已賺／進度資訊。
- 銷售紀錄的套組編號與品名優先依 `bundle_id` 顯示套組目前最新資料；套組編號／品名變更時，資料庫同步更新既有綁定銷售。
- 編輯銷售可直接勾選「結束套組」；一般付款結束為「結束」、免單付款為「免單結束」、直購維持「直購」，結束日期採該筆銷售日期。
- 免單結束與直購會自動同步套組狀態；「折扣全抵」作為獨立 0 元付款情境，不會自動結束套組。
- 銷售分析移除實收／找零欄位但保留尚餘提示；只有 jen 可從編輯視窗刪除銷售，刪除後由既有 Trigger 重新計算套組與月結資料。
- 套組管理新增「明細帳」，可查看累積營收、成本、毛利、刮數、歷史已刮基準與每筆交易；明細帳內可直接編輯銷售。
- 老闆寄抽到期日到達當天起視為停用，禁止新增套組與銷售，但仍可查看歷史資料；延長到期日可恢復營運。
- 月結新增雜項支出並納入「有效營收 × 90% − 雜項支出」公式，可辨識尚欠與已超付；月結頁面後續精簡為只保留必要數字、按鈕與表格。
- 營運總覽曾加入進行中套組已產生金額總計，作為後續實際收款追蹤功能的基礎。

## v5.0｜營運總覽、月結與結款制度
### 更新內容
- 整併原 v26～v39 的即時營運、月結、結款、登入恢復與圖表修正更新。
- 月結建立 10% 平台抽成／90% 應付老闆制度，付款方式為「待定」的交易暫不納入有效營收；支援同月份多次分段結款並永久保留結款紀錄。
- 月結畫面新增「有效營收、10% 抽成、應付老闆 90%、已付、尚欠」，並提供月中／本次結款入口；boss 只顯示必要營運資訊，jen 才顯示規則與技術說明。
- 修正月結已結按鈕與尚餘款計算；銷售可辨識未收款餘額，待定付款顯示整筆尚欠。
- Supabase JWT 過期或失效時加入自動 refresh session 與原請求重試，新 token 會同步到前端，避免總覽／銷售因登入狀態失效卡死。
- 直購正式視為套組已下套／已結束，銷售選擇直購時同步套組狀態與結束日期，並從可新增銷售的套組中移除。
- 營運功能順序整理為「套組管理 → 銷售分析 → 營運總覽 → 月結報表」；營運總覽集中顯示每月成本 vs 銷售額、套組成本／銷售額比較、套組狀態分布與進行中套組資訊。
- 修正 Chart.js 共用 options 造成數值軸異常、柱狀圖無數值等問題，改為每張圖表獨立設定並在切換頁面／老闆時重新計算。
- 銷售紀錄排序以銷售日期由新到舊為主，同日再依建立順序排列；後續成為固定時間軸功能的基礎。

## v4.0｜進階銷售流程與 Excel 差異同步
### 更新內容
- 整併原 v16～v25 的銷售表單、直購、待定、Excel 差異同步、排序與介面優化更新。
- 套組狀態加入直購，新增銷售完整支援現金、轉帳、街口、LINEPAY、免單結束、多元付款與找零。
- 修復新增銷售視窗與表單欄位存取，補強日期、套組、抽數、付款方式與實收不足等驗證。
- Excel 匯入改為差異化 Merge／Sync：Excel 未出現的資料不刪除、空白不覆蓋、狀態與結束日期以網站資料為主、歷史已刮採只增不減，相似但無法安全辨識的交易列為衝突。
- 更新說明、功能規則與開發型提示改為 jen 專屬；boss 只保留日常營運操作與必要成功／錯誤訊息。
- 套組排序從自然排序進一步調整為日期由新到舊、同日編號由大到小；新增銷售下拉與套組管理同步套用，並新增狀態篩選。
- 新增銷售支援「本筆完成後直接結束套組」與「待定付款」，銷售分析可直接編輯日期、套組、抽數、價格、折扣、付款、填表人與備註。
- Excel 日期解析改成只處理年月日，不再透過 UTC `toISOString()` 造成台灣日期偏移一天。
- 桌機側欄加入獨立垂直滾動與小螢幕縮排，手機版維持橫向老闆分頁。

## v3.0｜老闆管理、到期與月結基礎
### 更新內容
- 整併原 v10～v15 的老闆、到期日、月結、UI 與歷史刮數更新。
- 新增每位老闆寄抽到期日與總覽提醒；boss 可修改到期日。
- 老闆新增英文編碼並依編碼 A→Z 排序；新增套組時英文前綴自動帶入，只需輸入後段編號。
- 建立每月結算報表與圖表優先呈現，價格欄位統一為「一抽價格」。
- UI 改為深藍控制台＋淺色卡片風格，新增套組固定為進行中，狀態與結束日期移到套組編輯維護。
- 支援「歷史已刮數＋系統銷售刮數」雙軌計算，既有歷史進度可與新系統銷售累加。
- 「老闆管理」獨立成總管理區，不受目前選取老闆影響；點老闆可回到該老闆營運頁。
- 編輯套組若尚未設定結束日期，可依當時流程預設今日，為後續更嚴格的結束日期規則奠定基礎。

## v2.0｜銷售輸入與付款規則強化
### 更新內容
- 整併原 v5～v9 的 Excel 銷售匯入、折扣與付款方式更新。
- Excel 銷售匯入會略過只有公式的空白預留列；日期空白時沿用上一筆有效日期。
- 折扣欄改為輸入正數，由系統自動扣除；畫面固定以紅色負數視覺呈現，避免重複負號與輸入混亂。

- 新增「免單結束」付款方式，免單交易以銷售額 0、實收 0 儲存，且不可與其他付款方式混用。

## v1.0｜初版 Excel／Supabase 與營運核心
### 更新內容
- 整併原 v1～v4 的初版資料模型、套組／銷售分頁、毛利與多元付款功能。
- 整合既有 Excel 匯入邏輯，套組唯一性採「老闆＋套組編號」，不同老闆可使用相同編號；銷售依老闆與套組正確連結。
- Excel 品名出現 `#NAME?` 時，以對應套組品名補入；新增銷售後由 Supabase Trigger 自動更新套組總收入、總刮數與毛利。
- 建立套組管理與銷售分析獨立頁面，提供月別與套組別成本 vs 銷售額圖表，以及總銷售額、總成本、毛利、已售抽數 KPI。
- 毛利改為完全依銷售紀錄計算；沒有銷售的套組毛利為 0，不再手動維護已售抽數、銷售額與毛利。
- 支援已刮／總刮、進行中／結束／免單結束／腰斬等套組狀態。
- 銷售只需選擇套組即可自動帶入編號與品名，並支援現金、轉帳、街口、LINEPAY 多元付款、訂單總額、實收與找零計算。
