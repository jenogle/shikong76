## v24｜Excel 日期時區修正
- 修正 Excel 匯入後日期與系統日期相差一天的問題。
- Excel 日期改為只解析「年月日」，不再經過 `toISOString()` 的 UTC 時區轉換。
- Excel 數字日期序號以 UTC 日曆值拆解，避免台灣 UTC+8 時區造成前一天偏移。
- Excel 讀到 JavaScript Date 物件時改採本地年月日，不把本地午夜轉成 UTC。
- 同步統一新增套組、新增銷售的預設今日日期為本地日期格式，避免跨時區再次發生日期偏移。

## v23｜銷售快速結束＋待定付款＋銷售編輯＋套組篩選
- 新增銷售時可勾選「此筆銷售完成後直接結束套組」，不用再回套組管理修改狀態。
- 勾選直接結束後，一般付款會把套組改為「結束」；免單結束則改為「免單結束」，結束日期採本筆銷售日期。
- 結帳方式新增「待定」，適用線上訂單尚未完成付款；待定時可先建立銷售，實收與找零暫記為 0。
- 待定付款之後可透過「編輯銷售」改成現金、轉帳、街口、LINEPAY 或其他既有付款方式。
- 銷售分析的銷售紀錄新增「編輯」按鈕，可修改日期、套組、抽數、一抽價格、折扣、付款方式、填表人及備註。
- 修改銷售後，套組已刮數、營收、毛利與月結資料會由既有資料庫 Trigger 自動重新計算。
- 套組顯示排序改為「日期由新到舊」優先，同一天再依「套組編號由大到小」排序。
- 新增銷售的套組下拉選單同步採「日期由新到舊 → 編號由大到小」。
- 套組管理新增狀態篩選：全部狀態、進行中、結束、免單結束、腰斬、直購。
- README / VERSION_HISTORY 持續採最新版本在最上方的倒敘累積紀錄。

## v1

本版已將目前兩份 Excel 匯入邏輯整合：
- `WEI寄抽.xlsx` → 老闆：WEI（4 筆套組、1 筆銷售）
- `益(1).xlsx` → 老闆：益（174 筆套組、156 筆銷售）

## 重要架構更新
- 套組編號不再全域唯一，而是「老闆 + 套組編號」唯一，因此不同老闆可以有相同編號。
- 銷售紀錄會依「老闆 + 編號」連到正確套組。
- 原 Excel 銷售紀錄中出現的 `#NAME?` 品名，匯入時改用對應套組的品名。
- 新增銷售後，Supabase trigger 會自動更新對應套組的總收入、總刮數與毛利。
- 系統仍保留「未分配」老闆，方便日後處理尚未歸屬的舊資料。

## 全新專案安裝
1. 在 Supabase SQL Editor 執行 `supabase.sql`。
2. 在 Supabase 建立登入帳號（Authentication → Users）。
3. 使用 `index.html` 開啟／部署前端。
4. 前端使用 Supabase Project URL + Publishable Key。

## 已有專案更新
若你已經執行過舊版 `supabase.sql`，建議先備份目前資料，再執行 `data_update_WEI_益.sql`。
這個更新檔會建立／更新 `WEI`、`益` 兩位老闆並匯入兩份目前 Excel 資料。

不要把 Service Role / Secret Key 放進前端。
